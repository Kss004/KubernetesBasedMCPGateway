# AGENTS.md — Harbor (MCP gateway on Kubernetes, Urumi take-home)

Rules for every coding agent working in this repo. Keep this file short. The plan, decisions and status live in `progrestillnow.md`; do not copy them here.

## 1. Read first

1. Read `progrestillnow.md` before doing anything: sections 0, 4, 5 (decisions), 6 (schedule) and 7 (tasks), plus section 12 (in flight).
2. Work on **one task at a time**, using its ID (for example T1.3). Do not start a phase before the previous phase's verify passes.
3. If a decision in `progrestillnow.md` seems wrong, say so and explain why. Do not silently work around it or change it.

## 2. The human is learning

This is AI-native coding with the human learning alongside, and the human must defend every design choice live in Round 2. So:

- Before writing code for a task, state the **context, constraints, the decision, the rejected alternatives, and what is uncertain**.
- Prefer one small, understood change over a large opaque one.
- After a task, give a plain explanation of what was built and the one non-obvious reason behind it. The human adds it as one line to the task's row.
- Do not hide complexity. If something is a shortcut, mark it with a `// ponytail:` comment naming the ceiling and the upgrade path.

## 3. Hand-written zones (do not generate)

The human writes these personally. In these areas, only discuss, review or explain; do not write or edit the code:

- T3.4 aggregator, T3.5 router
- T4.1 key handling, T4.3 dashboard login

Free to delegate: the dashboard UI, Helm templates, Dockerfiles, Makefile targets, scaffolding.

## 4. Never guess

- Do not invent versions, flags, API shapes, image tags or file paths. Look them up in docs, the repo or the tool's own help output, or say clearly that it is **unverified**.
- Versions are recorded in `docs/versions.md` (T0.4). Copy from `npm view` / `helm show chart` / release notes, never from memory.
- Anything listed under "Not yet verified" in section 14 of `progrestillnow.md` stays unverified until a command or document confirms it.
- Say what evidence supports a claim. "I believe" is acceptable; presenting a belief as fact is not.

## 5. Verify before claiming done

- Every task has a verify command in `progrestillnow.md`. Run it and report the actual output.
- No evidence, not done. If a verify fails, **stop and report**; do not loosen the check or work around it.
- Do not mark a task or phase "Done" in the status board yourself. The human confirms.

## 6. Secrets and security (hard rules)

- Never put a secret in source, values files, Dockerfiles, logs or commit messages. Secrets are generated by Helm or created out-of-band with `kubectl create secret`. See the Secrets map in section 4 of `progrestillnow.md`.
- Never read, print or commit `.env` files or Secret contents, except where a task explicitly requires the human to do so.
- Kubernetes Secrets do not cross namespaces. Each secret lives where its consumer lives.
- API keys are stored as SHA-256 hashes (not bcrypt). Passwords use bcrypt or argon2. Upstream credentials are encrypted with AES-256-GCM using Node `crypto`.
- Client tokens are never forwarded to upstreams. Upstream credentials never reach a client or the browser.
- Do not store tool arguments or results in the audit log (D22).

## 7. Per-workload checklist

Apply the moment a Deployment or StatefulSet is written, not at the end:

- resource requests and limits
- readiness and liveness probes
- `securityContext` with `runAsNonRoot` and dropped capabilities where the image allows
- `automountServiceAccountToken: false`
- Secret references only
- labelled namespace
- ingress default-deny NetworkPolicy in the namespace

## 8. Conventions

- TypeScript, Node 24, npm workspaces. Services under `apps/`, charts under `charts/`, docs under `docs/`.
- Ponytail rule: no ORM, no UI framework, no crypto library, no retry library, no LLM SDK, no DI container. Plain `fetch`, plain SQL, Node `crypto`, `node --test`.
- Tool names are `<slug>__<tool>` (D5). The MCP SDK is pinned to the stable 1.x line.
- The gateway is stateless: create a fresh server and transport per request (D6).
- Domains are `*.localhost`. Images are built locally and loaded with `kind load` (D16, D17).
- Shell scripts and Helm templates use LF line endings. Never work from `/mnt/c`; the repo lives in the WSL filesystem.
- Small commits, one task per commit, message prefixed with the task ID (for example `T1.3: store chart`).

## 9. Dangerous commands: ask first

Ask the human before running any of these:

- `kubectl delete`, `helm uninstall`, `kind delete cluster`, `make reset`
- `git push`, `git reset --hard`, `git rebase`, `rm -rf`
- anything that touches the Docker daemon beyond building, running and loading images

## 10. Agent roles (if the custom agent files exist)

- **Plan (built-in):** writes the task note (context, constraints, decision, alternatives, unverified items, verify command). Never edits code.
- **Build (built-in):** implements one approved task and runs its verify command.
- **reviewer (read-only):** checks the diff against the decisions, the section 6 and 7 rules, and the hand-written zones.
- **teacher (read-only):** explains the diff and asks three questions a Round 2 interviewer would ask.
- **Scout (built-in):** looks up external docs (MCP spec, WooCommerce REST, Helm, Kubernetes).

## 11. End of every session

1. Update the status board and "In flight" (section 12) in `progrestillnow.md`.
2. Record anything newly verified or still unverified in section 14.
3. Commit and report what changed, what was verified with evidence, and what is next.
