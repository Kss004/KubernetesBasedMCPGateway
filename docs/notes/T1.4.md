# T1.4 — bootstrap Job (note; Job is cluster state, chart is git)

- Job (`wordpress:cli-2.12.0`, one-shot, idempotent): core install → pin
  WooCommerce 11.2.1 zip → activate → pretty permalinks → country US:CA,
  currency USD → COD enabled → US flat-rate shipping zone → REST keys into
  `store-woo-rest` via K8s API (least-privilege SA/Role/Binding).
- Verify: `kubectl logs job/store-bootstrap` → `secret created`;
  `store-woo-rest` has 2 keys; DB row `read_write`, user 1.
- Gotchas (each cost a Job iteration):
  1. `wp-config.php` reads DB settings via `getenv_docker()` at runtime —
     the Job needs the same `WORDPRESS_DB_*` env as the wordpress pod.
  2. cli image runs as uid 82, docroot owned by uid 33 → Job sets
     `runAsUser: 0` (one-shot admin task; web runtime untouched).
  3. `resourceNames` is ignored by the API server on `create` (real POST 403
     while `can-i` says yes) → Role grants bare `create`, name-scoped
     `get`/`delete`. Blast radius stays inside `urumi-store`.
- Non-obvious (read from WC 11.2.1 source, not memory): over plain HTTP
  `is_ssl()` is false so `authenticate()` skips Basic entirely
  (`class-wc-rest-authentication.php:212`) — query-string ck/cs also lives
  inside the SSL-gated basic path. woo-mcp (T2.2) must sign OAuth 1.0a
  one-legged requests (HMAC-SHA256, `consumer_secret&`, query-string params).
