# T1.2 — ingress-nginx on kind (note; controller is cluster state, not git)

- Install: `helm repo add ingress-nginx https://kubernetes.github.io/ingress-nginx`
  `helm upgrade --install ingress-nginx ingress-nginx/ingress-nginx --version 4.15.1 -n ingress-nginx --create-namespace --set controller.hostPort.enabled=true --set-string controller.nodeSelector.ingress-ready=true --set-string controller.tolerations[0].key=node-role.kubernetes.io/control-plane --set-string controller.tolerations[0].operator=Exists --set-string controller.tolerations[0].effect=NoSchedule --set controller.terminationGracePeriodSeconds=0`
- Gotcha hit: `--set controller.nodeSelector.ingress-ready=true` fails server-side apply (bool vs string); must be `--set-string`.
- Verify: `curl --resolve shop.localhost:80:127.0.0.1 http://shop.localhost/` → `404 Not Found` from `nginx` (controller hit, no Ingress routes yet — correct at this stage).
- Non-obvious: WSL curl does NOT resolve `*.localhost` (needs `--resolve`); browsers do. `/mcp` + `/api/chat` get `proxy-buffering: off` + long `proxy-read-timeout` annotations when those Ingresses land (P3/P6).
