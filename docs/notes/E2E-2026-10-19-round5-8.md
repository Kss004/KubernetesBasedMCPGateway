# E2E rounds 5-8 (2026-10-19/20)

These rounds were run by a separate "Claude Chrome extension end-to-end testing" session in Chrome
plus a terminal, on kind-urumi. Its reports came back over a one-way link, so they are summarised
here from those reports. Each finding names the commit that fixed it.

## Round 5: gateway 0.4.9 (c77be44). 21/23 pass, 2 bugs

- **Bug 1, MEDIUM: wrong day total in chat.** The order list was right on all 3 runs, but the
  model's own sum was wrong ($145.94, $134.95, $150.96 against a true $161.38).
  Fix in `eb9b540`:
  - `list_orders` returns `{count, total, complete, orders}`, with the total summed in cents;
  - the default page holds 100 orders;
  - the prompt says to never add up amounts.
- **Bug 2, MEDIUM: Zod validation errors returned 500 with the raw issue JSON.** Affected
  routes: servers, users, password, keys and login. Fix in `f5326ef`: `errors.ts` maps a
  ZodError to 400 with `invalid input: field: reason`, and the password input has `minLength 8`.
- **Notes:**
  - logout accepted a form post (`346222c`, now 403);
  - `get_order` shows customer names and addresses to members (by design, documented in
    `695e6b3`);
  - noisy cold-start migrate lines (expected).
- **Passed:** health and headers, A's product + COD order #51, "orders today" 3/3 order lists,
  the two-server prompt, B's 403s and 9 tools with `-32000` on writes, revoke giving 401 plus a
  `revoked_key` row, disable/enable, SSRF checks (all 400), logout invalidation, lockout (429).

## Round 6: gateway 0.4.10 (2634d62). All round 5 fixes verified, 1 new MEDIUM

- **Verified:**
  - day total exact on 3/3 runs (16 orders, $204.62, matched against `wc_get_orders`);
  - 400s with short messages, form logout gives 403;
  - full DoD re-run passes, including B over `/mcp` (9 tools, list/convert/add) and a disabled
    mock (B's client 9 → 5 tools);
  - audit attribution correct.
- **MEDIUM: narrated reasoning and a spurious tool call.** With mock disabled, "convert 100 USD
  to EUR" called `everything__add` and the reply narrated the model's reasoning, quoting our
  "call the tool now" rule. Fix in `9ea413e` (gateway 0.4.11):
  - the prompt now says "if no tool fits, say so in one sentence and do not call a tool; answer
    only";
  - `<think>` blocks are stripped.
- **Cosmetic:** the Set-password button did not respect `minLength`. Fixed in `0d87acd`: the
  button is disabled under 8 characters.
- **Not fixed (user's call):** an unauthenticated `/mcp` call with a malformed body gets 400
  before the auth check.

## Round 7: gateway 0.4.11 (2e5fdb3). All 5 retest items pass, no new bugs

- **Passed:**
  - with mock disabled, the repro gives a plain refusal with no tool call (3/3);
  - with mock enabled, conversion works (100 USD = 92 EUR);
  - B's create attempt is refused in one sentence;
  - "orders today" is exact (17 orders, $214.61);
  - the Set-password button is disabled at 7 characters.
- **Notes:**
  - one flaky unit-test run: the bounds were loosened to 5s in `40942b5`, since the tests use
    300-400ms timeouts;
  - the 429 log line did not say which limit hit. It now logs `retry-after` and `x-ratelimit-*`
    (`71f0fa6`, gateway 0.4.12).
- **Groq free tier:** 6 of 12 prompts got "model is busy". This led to the DeepSeek switch.

## Round 8: gateway 0.4.13 (c04e6a0, DeepSeek v4.1 flash on OpenCode Go). ALL PASS

- **Baseline:** 20 pods Running, smoke 13/13, unit tests 52/52 and 3/3.
- **A:**
  - created "Round8 Floor Lamp" 41.75 (id 62) and placed COD order #63;
  - "orders today" was exact 3/3 (2 orders, 51.74), and two prompts ran back to back with no
    rate limiting;
  - the two-server prompt works.
- **B:**
  - chat refusal in one sentence with no tool call;
  - 403 on admin APIs;
  - over `/mcp`: 9 tools, `list_orders` `{count:2,total:"51.74"}`, convert and add work, writes
    get `-32000 forbidden`, a bad or missing key gets 401.
- **Disable mock:** A 7 tools, B 5 tools. Chat declines conversion with no tool call. After
  enable: 11 / 9.
- **Kill upstream** (scale everything-mcp to 0 at 15:01:02):
  - Unreachable at 15:01:12 (10s);
  - meanwhile woo answered in 161ms, mock in 11ms, and everything failed fast with `-32000
    server unreachable` in 5ms;
  - after scaling back: Ready at 15:01:45, Connected at 15:01:54.
- **Revoke:** 200 before, 401 after, and a `revoked_key` row.
- **Audit:** 16 rows, all correctly attributed. B's view shows only B's rows, even with
  `?user_id=<A>`.
- **Security:** SSRF 400s, short validation 400s, duplicate slug 409, form content type 403,
  copied or tampered cookies 401 after logout, lockout 429 then recovery after 65s.
- **Logs:** zero error lines in 25 minutes.
- **Notes:**
  - the Groq fallback was manual. It became automatic in `c263c1f` (gateway 0.4.14), verified
    live with a deliberately broken primary;
  - OpenCode Go's terms: the user accepted the risk for the demo (D10).
